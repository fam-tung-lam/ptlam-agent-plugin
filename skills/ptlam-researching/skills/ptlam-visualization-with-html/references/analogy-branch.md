# The Analogy Branch

This reference owns how an HTML explainer consumes an approved analogy while
keeping the verified literal model authoritative.

## When the user requests a new analogy

Resume the main workflow from the approved mapping, story, and caveats.

Return a material analogy gap to that branch. Do not repair it here.

## When the user supplies an analogy

Consume only the mapping, story, caveats, or alternatives approved for the
supplied domain. Return a material gap for repair; do not create a parallel
acceptance rule or render a failed mapping as though it were explanatory
evidence.

## Finish

Finish when the artifact has one verified literal model, and either no analogy
or one analogy approved by the mapping gate.
