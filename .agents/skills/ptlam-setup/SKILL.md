# PTLam Project Setup

Install PTLam's general working preferences into one project. This workflow
creates or refreshes project instruction files, so run it only when the user
explicitly asks to initialize or update those instructions.

## 1. Resolve the target and current state

1. Resolve the project root from the user's explicit path or the active
   workspace. Target one project root, never a home directory or a parent that
   contains several projects.
2. Inspect `AGENTS.md`, `AGENTS.override.md`, and the working-tree state when the
   project uses version control. Preserve unrelated and in-progress changes.
3. Read [PTLam's general agent instructions](references/PTLAM_AGENTS.md) in
   full. This reference owns the exact managed contents of
   `AGENTS.override.md`.

Complete this step when the target root is unambiguous, both destination files
have been inspected, and the bundled instructions are loaded.

## 2. Create or refresh `AGENTS.override.md`

1. If `AGENTS.override.md` is absent, create it as an exact copy of
   `references/PTLAM_AGENTS.md`.
2. If it already matches the reference byte for byte, leave it unchanged.
3. If it differs and contains the `PTLAM-INIT:MANAGED` marker, replace the file
   with the current reference. The marker identifies the file as generated by
   this skill; project-specific instructions belong in `AGENTS.md`.
4. If it differs and lacks that marker, preserve it and report the collision.
   Replace an unmarked file only with explicit user authorization.

Complete this step when `AGENTS.override.md` exactly matches the bundled
reference, or an unmarked pre-existing file has been preserved and reported as
the only blocking collision.

## 3. Link the override from `AGENTS.md`

Ensure `AGENTS.md` contains exactly one copy of this managed block:

```markdown
<!-- PTLAM-INIT:START -->
## PTLam preferences

Always read and apply [PTLam's general agent instructions](AGENTS.override.md)
before following the rest of this file. When they conflict, prefer
`AGENTS.override.md` over `AGENTS.md`.
<!-- PTLAM-INIT:END -->
```

1. When `AGENTS.md` is absent, create it with `# Project agent instructions`
   followed by the managed block.
2. When the file exists and contains the marker pair, replace only the marked
   block with the canonical block above.
3. When the file exists without the marker pair, insert the block after its
   opening level-one heading when present, or at the beginning otherwise.
4. Preserve all content outside the managed block. If an unmarked instruction
   already links to `AGENTS.override.md` and states both the always-load and
   precedence rules, treat it as equivalent and do not add a duplicate.

Complete this step when `AGENTS.md` links to the sibling override, tells agents
to always load it, gives it precedence over `AGENTS.md`, and retains all
unrelated project guidance.

## 4. Verify and report

1. Confirm both files exist at the resolved project root.
2. Confirm `AGENTS.override.md` matches `references/PTLAM_AGENTS.md` byte for
   byte and contains exactly one `PTLAM-INIT:MANAGED` marker.
3. Confirm the relative link in `AGENTS.md` resolves, the load and precedence
   instruction is present exactly once, and the managed markers are balanced.
4. Inspect the final diff and report the target root, created or refreshed
   files, verification performed, and any preserved collision.

Complete the workflow when the two files form an idempotent installation of the
bundled preferences, unrelated project instructions remain intact, and the
report accounts for every changed or blocked file.
